## 1. 文档规范

### 1.1 目录约定

| 路径 | 用途 |
|------|------|
| `Docs/` | 仓库级规范、流程、设计说明 |
| `Docs/Markdown/` | 系列化技术笔记（按编号排序） |
| `Docs/README.md` | 文档入口 |

### 1.2 系列文档命名

```
Docs/Markdown/NN-标题.md
```

- `NN` 为两位顺序号：`01`、`02`、`03`……
- 标题使用中文短语，不加空格，例如 `02-字符串编码与线程工具.md`
- 新增文档必须同步更新 `Docs/Markdown/README.md` 索引
- 编号只增不改，避免外部引用失效

### 1.3 内容要求

- 面向"没上过这节课的人"，先讲**为什么**，再讲**怎么做**
- 涉及代码时给出真实文件路径，不贴伪代码
- 图表优先使用 Mermaid（GitHub / VSCode 均可渲染）
- 结论、坑点用表格或列表收口，避免长段落

## 2. 目录结构

```
CppGameServer/
├── CMakeLists.txt              # 根入口（必须叫这个名字，大小写敏感）
├── Cmake/                      # CMake 辅助脚本
│   └── CASOptions.cmake        # 统一的编译/链接选项（INTERFACE 库）
├── CAS/                        # 核心库
│   ├── CMakeLists.txt
│   ├── Include/CAS/            # 公开头文件（对外安装）
│   │   ├── Export.h            # CAS_API 导出宏
│   │   ├── Macros.h            # 断言宏 + 基础类型别名
│   │   ├── Mutex.h
│   │   ├── Logger/
│   │   └── Utils/
│   └── Source/                 # 内部实现（不对外安装）
│       ├── Logger/
│       └── Utils/
├── Tests/                      # 测试 / 手动观测程序
├── Tools/                      # 辅助工具
├── Docs/                       # 文档
└── build/                      # 构建产物（.gitignore 忽略）
```

**硬性规则**

- 源码目录与构建目录**必须分离**，禁止在仓库根直接 `cmake ..`
- 公开头文件放 `Include/`，内部头文件与实现放 `Source/`
- `Source/` 通过 `target_include_directories(... PRIVATE ...)` 加入包含路径，不对外暴露

## 3. 命名规范

### 3.1 总表

| 类别 | 规则 | 示例 |
|------|------|------|
| 命名空间 | PascalCase | `CAS`、`CAS::Detail` |
| 类 / 结构体 / 枚举 | PascalCase | `Logger`、`LogRecordView`、`LogLevel` |
| 枚举值 | `LOG_LV_` + 大写 | `LogLevel::Level::LOG_LV_DEBUG` |
| 自由函数 / 静态成员函数 | PascalCase | `GetThreadId`、`MakeStdoutAppender`、`GetLogger` |
| 类的成员函数 | camelCase | `shouldLog`、`setLevel`、`addAppender` |
| 成员变量 | `m_` + camelCase | `m_impl`、`m_mutex`、`m_appenders` |
| 静态成员变量 | `s_` + camelCase | （暂无） |
| 全局变量 | `g_` + camelCase | `g_loggerRegistry` |
| 线程局部变量 | `t_` + camelCase | `t_thread_name` |
| 常量 | UPPER_SNAKE_CASE | `DEFAULT_LOG_PATTERN`、`MAX_UNICODE_CODE_POINT` |
| 宏 | UPPER_SNAKE_CASE | `CAS_ASSERT`、`ASSERT_RETVAL2` |
| 模板参数 | PascalCase | `template <typename Item>` |
| 文件名 | PascalCase | `Logger.cpp`、`StringUtils.h` |

### 3.2 补充说明

- **成员函数用 camelCase、自由函数用 PascalCase**：这是本项目当前的实际风格，用于区分"对象行为"和"模块入口"。
- **非拥有视图**在变量名中体现意图：`formatted_record`（`string_view`）、`record`（`LogRecordView`）。
- **布尔值**用 `is/has/can/should` 前缀：`shouldLog`、`canWrite`。
- 禁止拼音、禁止无意义缩写（`tmp`、`data2`）。

## 4. 文件与头文件规范

### 4.1 头文件保护宏

| 位置 | 规则 | 示例 |
|------|------|------|
| `Include/` | `CAS_INCLUDE_<路径>_H` | `CAS_INCLUDE_CAS_UTILS_STRING_UTILS_H` |
| `Source/` | `CAS_SRC_<路径>_H` | `CAS_SRC_LOGGER_LOGGER_H` |

统一使用 `#ifndef / #define / #endif`，并在 `#endif` 后写注释说明对应的宏。

### 4.2 include 顺序

```cpp
// 1. 本文件对应的头文件
#include "Logger/LoggerImpl.h"

// 2. C 标准库 / C++ 标准库（按字母序）
#include <algorithm>
#include <memory>
#include <string_view>

// 3. 项目公开头
#include <CAS/Export.h>
#include <CAS/Macros.h>

// 4. 项目内部头
#include "Logger/Formatter.h"
```

- 公开头文件用 `<CAS/...>`，内部同目录头文件用 `"..."`。
- 每个头文件**自包含**：单独 include 也能编译通过（不依赖调用方的 include 顺序）。

### 4.3 扩展名

- 实现文件统一 `.cpp`（不使用 `.cc`）。
- 头文件统一 `.h`（`Appender.hpp` / `Logger.hpp` 为历史遗留，见[待确认事项](#14-待确认事项)）。

### 4.4 前置声明

- 头文件中能前置声明就不要 include，减少编译依赖：

```cpp
namespace Detail { class LoggerAccess; }   // 前置声明
```

- 但**继承、成员对象、`unique_ptr<T>` 的析构**必须看到完整定义。

## 5. 命名空间与可见性

### 5.1 命名空间层级

```
CAS                      // 全部公开 API
└── Detail               // 内部实现细节，禁止业务代码直接使用
```

### 5.2 可见性规则

| 内容 | 位置 | 是否对外 |
|------|------|---------|
| 公开类 / 工厂函数 | `Include/CAS/...` | 是，标注 `CAS_API` |
| 内部实现头（`Impl`、`Access`） | `Include/CAS/.../xxx.h` 或 `Source/` | **否** |
| 实现文件 | `Source/` | 否 |

### 5.3 内部访问的两种模式

- **Pimpl**：公开类只持有 `std::unique_ptr<Impl>`，实现细节全在 `.cpp`。
- **Access 类（passkey / friend）**：需要跨类访问私有成员时，引入单一入口类，而不是到处 `friend`。

```cpp
class CAS_API Logger final
{
    ...
private:
    std::unique_ptr<Impl> m_impl;
    friend class Detail::LoggerAccess;   // 唯一入口
};
```

禁止在公开头文件中 `using namespace`。

## 6. C++ 语言规范

### 6.1 语言标准

- 统一 **C++20**，禁止使用 C++23 及以上特性（除非全平台工具链确认支持）。
- 允许 GNU 扩展（`CMAKE_CXX_EXTENSIONS ON`），但**跨平台代码不得依赖**平台专属扩展。

### 6.2 必须遵守

| 规则 | 说明 |
|------|------|
| RAII | 资源用对象管理，禁止手动 `new`/`delete` 裸用 |
| `const` 正确性 | 不修改成员的方法必须 `const` |
| `noexcept` | 明确不会抛的函数标注，尤其是移动构造、析构、热路径函数 |
| `explicit` | 单参数构造函数默认加，除非确实需要隐式转换 |
| `[[nodiscard]]` | 返回值有意义的函数（getter、工厂）必须加 |
| `override` | 重写虚函数必须写 |
| `nullptr` | 禁止 `NULL` / `0` |
| 范围 for | 优先于下标循环，除非需要索引 |

### 6.3 禁止事项

- 禁止 `using namespace std;`（头文件中绝对禁止，`.cpp` 中也不推荐）
- 禁止裸 `new` / `delete`（工厂内部配合智能指针的极少数场景除外）
- 禁止 C 风格强制转换，统一 `static_cast` / `reinterpret_cast` / `const_cast`
- 禁止在头文件中定义非 `inline` 的全局对象
- 禁止用 `volatile` 做线程同步（用 `std::atomic`）

### 6.4 设计模式约定

| 模式 | 使用场景 | 现有示例 |
|------|---------|---------|
| Pimpl | 公开类隐藏实现、稳定 ABI | `Logger`、`Appender` |
| NVI | 基类保证不变量，派生类只实现钩子 | `Appender::Impl`（`append` 非虚 + `writeUnlocked` 纯虚） |
| 策略 | 可变算法 | `Formatter::FormatItem` |
| 工厂 | 控制对象创建 | `MakeStdoutAppender`、`MakeFileAppender` |
| 单例 | 全局唯一管理器 | `GetLoggerManager()`（函数内静态） |

## 7. 错误处理与断言

### 7.1 基本原则

| 错误类型 | 处理方式 |
|---------|---------|
| 编程错误（不该发生） | 断言，Debug 中止 |
| 可恢复错误（非法输入） | 返回错误码 / 空值 / `optional` |
| 资源失败（内存、IO） | 记录日志并降级，不抛给业务层 |
| 基础库对外接口 | `noexcept`，内部 `try/catch` 兜底 |

### 7.2 断言宏

| 宏 | 失败行为 |
|----|---------|
| `CAS_ASSERT(cond)` | 打印 `文件:行号` + 条件，`assert` |
| `CAS_ASSERT2(cond, info)` | 同上，附带自定义信息 |
| `ASSERT_RETVAL2(cond, val, msg)` | 断言 + `return val` |
| `ASSERT_RETNONE2(cond, msg)` | 断言 + `return` |
| `ASSERT_NOEFFECT2(cond, msg)` | 只断言，不返回 |
| `ASSERT_CONTINUE2` / `ASSERT_BREAK2` | 断言 + `continue` / `break` |

> `ASSERT_RETVAL*` 的 `return` 在断言之后**无条件执行**，因此 Release 下依然会返回失败值。

### 7.3 断言使用边界

- **可以断言**：内部不变量、指针非空、枚举值合法、状态机前置条件。
- **不要断言**：用户输入、网络数据、文件内容——这些必须走错误处理分支。

## 8. 并发规范

### 8.1 锁的选择

| 场景 | 选择 |
|------|------|
| 读多写少的配置（appender 列表、formatter） | `std::shared_mutex` + `shared_lock` / `unique_lock` |
| 保护单一 sink 的写入 | `std::mutex` + `lock_guard` |
| 极短临界区、无阻塞 | `Spinlock`（`CAS/Mutex.h`） |

### 8.2 原子变量与内存序

| 场景 | 内存序 |
|------|--------|
| 独立标量（等级开关、计数） | `relaxed` |
| 作为"门闩"发布其他数据 | store `release` + load `acquire` |
| 多原子变量需要统一顺序 | `seq_cst` |

**必须理解**：`std::shared_ptr` 的引用计数是原子的，但**同一个 `shared_ptr` 对象被多线程读写仍然是 data race**。需要共享所有权时，在锁内拷贝到局部变量再使用。

### 8.3 锁的使用纪律

- 临界区尽量短，**不在持锁期间做 IO 或回调**（现有 `Logger::Impl::submit` 在锁内做格式化与写盘，属于已知权衡，见[待确认事项](#14-待确认事项)）
- 统一使用 RAII 锁（`lock_guard` / `unique_lock` / `shared_lock`），禁止手动 `lock`/`unlock`
- 多个锁必须固定加锁顺序，避免死锁

### 8.4 线程局部存储

- 线程私有状态优先用 `thread_local`，天然免锁
- `thread_local` 的**动态初始化在首次访问时发生**，不要在静态初始化阶段假设它已就绪

## 9. 资源管理与所有权

| 语义 | 类型 |
|------|------|
| 独占所有权 | `std::unique_ptr` |
| 共享所有权 | `std::shared_ptr` |
| 非拥有观察 | 裸指针 / 引用 / `std::string_view` |
| 可能失效的观察 | `std::weak_ptr` |

**`string_view` 使用约定**

- 只在**同步调用期间**有效，跨线程/异步队列传递前必须拷贝
- 函数返回 `string_view` 时，必须在注释中写明有效范围

## 10. API 设计规范

1. **公开类默认 `final`**，除非明确允许继承。
2. **身份型对象禁止拷贝/移动**（如 `Logger`、`Appender`），用 `shared_ptr` 共享。
3. **构造函数尽量私有**，通过工厂函数创建（`Appender`）。
4. **Pimpl 类的析构函数必须定义在 `.cpp`**（`Impl` 完整处），避免 `unique_ptr<Incomplete>` 报错。
5. **接口方法分组**：配置（低频）、数据（高频）、生命周期（构造/析构）分开注释。
6. **不暴露内部类型**：公开头文件中不出现 `Detail::` 类型作为参数（`LoggerAccess` 除外，它本身就是内部桥）。

## 11. 注释与文档

### 11.1 代码注释

- 使用**中文**，解释"为什么"，不解释"是什么"。
- 公开 API 使用 Doxygen 风格：

```cpp
/**
 * @brief 获取当前线程 ID
 * @return Linux 下为内核 TID，Windows 下为系统线程 ID
 */
[[nodiscard]] CAS_API u64 GetThreadId() noexcept;
```

- 每个文件顶部可省略版权头，但**复杂算法必须写思路**（如 UTF-8 解码的各层校验）。
- 注释与代码不同步时，**删注释而不是留错误注释**。

### 11.2 文档

- 架构、模块设计、踩坑记录写入 `Docs/Markdown/NN-*.md`
- 规范变更同步更新本文档

## 12. Git 规范

### 12.1 提交信息

```
<type>(<scope>): <subject>
```

| type | 含义 |
|------|------|
| `feat` | 新功能 |
| `fix` | 修复 bug |
| `refactor` | 重构（不改变行为） |
| `docs` | 文档 |
| `test` | 测试 |
| `build` | 构建脚本 / CMake |
| `chore` | 杂项 |

示例：

```
feat(logger): add file appender with fdatasync
fix(utils): truncate thread name at UTF-8 boundary
docs(markdown): add 02 string and thread utils
```

### 12.2 提交纪律

- 一个提交只做一件事
- 提交前确保 `cmake --build` 通过
- 不提交 `build/`、IDE 配置、二进制产物（见 `.gitignore`）

## 13. 构建规范

### 13.1 标准命令

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug
cmake --build build -j$(nproc)
```

Release：

```bash
cmake -S . -B build-release -DCMAKE_BUILD_TYPE=Release
cmake --build build-release -j$(nproc)
```

### 13.2 构建选项

| 选项 | 默认 | 说明 |
|------|------|------|
| `CAS_BUILD_TESTS` | ON | 构建 `Tests/` |
| `CAS_BUILD_TOOLS` | ON | 构建 `Tools/` |
| `CAS_BUILD_EXAMPLES` | ON | 构建示例 |
| `ENABLE_COVERAGE` | OFF | Debug 下开启 gcov |

### 13.3 编译选项

统一由 `Cmake/CASOptions.cmake` 的 `CAS_options` INTERFACE 库提供，业务目标只需：

```cmake
target_link_libraries(<target> PRIVATE CAS_options)
```

禁止在各 `CMakeLists.txt` 中零散添加 `-O2`、`-Wall` 等选项。

### 13.4 编译器

当前 `CMakeLists.txt` 硬编码 `/usr/bin/gcc` / `/usr/bin/g++`，不具备可移植性，**后续应改为探测式**（见待确认事项）。
